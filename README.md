# Catalog Studio — カタログ編集ワークスペース

IDMLを起点に、販促担当が紙面を見ながら原稿を編集し、開発部門への質問と制作会社への指示をまとめるローカル実証アプリです。InDesignを起動せずに動作します。

## 起動

初回はPython 3.12以降を用意し、リポジトリのフォルダーで以下を実行します。

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe server.py --data data-live --port 8877
```

Linux/macOSでは `.venv/bin/python` を使います。カタログ原本、リンク画像、編集データ、検証画像はリポジトリに含めません。取り込み用IDML/ZIPは別途用意してください。

PowerShellでこのフォルダーの `./start.ps1` を実行し、http://127.0.0.1:8877 を開いてください。停止は起動した端末で Ctrl+C。初回取り込みは画面の「IDML取込」、または `./start.ps1 -ImportFile 'C:\path\catalog.zip'`。既存カタログがある場合、起動時の自動取り込みは省略します。

ランチャーは `data-live/` にSQLite・原本・画像を保存します。バックアップは停止後、このフォルダー全体をコピーしてください。以前の検証用 `data/` と `.qa/` は独立しています。server.pyを直接起動するときも `--data data-live` を指定してください。

Python 3.12以降と requirements.txt のライブラリを使用します。このPCでは同梱ランタイムで動作確認済みです。任意のPDF参照表示にはPATH上の `pdftoppm`（Poppler）を使います。外部CDN・クラウドへのデータ送信はありません。

## 体験する順番

1. 販促としてログインし、原版PDFと構造化HTMLの表示を切り替える。
2. 紙面の文字を選択し、右側で上書き・部分置換。保存後も原本参照を保持。
3. 選択済みのボックスをドラッグ、寸法指定、別ページへ移動。長い文章は「次ページへ流す」で分割位置を確認して実行。
4. 原稿受け取り画面でExcel・CSV・画像をアップロード。表の行から指示原稿を作り、元ファイル・シート・行を残す。
5. 対象箇所へ質問を付け、開発役で回答。解決後の訂正回答は再確認に戻る。
6. ページネーションで新規ページ・並び替え。調査画面で型番を検索し、掲載箇所に移動。
7. 制作指示ZIPを保存。編集前後のHTML、指示JSON/CSV、原本IDML、リンク画像原本、添付資料をまとめる。外部へ送信はしない。
8. 社内公開後、閲覧役で公開済み版を確認。以後の未公開編集は閲覧役・MCPに出ない。

同時編集の競合は上書きせずエラーにします。保存操作単位で履歴が残り、直前の自分の編集を取り消せます。コメントはアプリ内の記録で、メール等の通知はありません。

画面上部の「すべて元に戻す」は、確認後に現在のカタログの全紙面を取り込み直後へ戻します。追加ページ・配置・文章・画像の変更と現在の制作指示一覧を取り消します。原稿・添付資料・やり取り・公開済み版は保持し、反映済み原稿と紙面に関するやり取りは再確認に戻します。直後の「元に戻す」で復元操作自体も取り消せます。

## 制限

- HTMLの配置・折り返しは編集指示のプレビュー。InDesignと同一のフォント・禁則・組版・色再現を保証しません。IDMLへの自動書き戻しは未実装です。
- 複雑な連結フレームは原稿を重複カウントせず、配置を要確認として表示します。混在表の周辺文字も位置は推定です。マスターページや複雑な効果等には未対応部分があります。
- PSDはPillow対応形式と今回の非圧縮RGB16bit合成画像をプレビュー化。元PSDは別に保持します。未対応形式は取り込み警告を確認してください。
- Excelはxlsxの読み取りプレビュー（先頭10シート・200行・40列）、CSV対応。xlsはxlsxへ変換してください。数式は実行しません。検索結果の表示・CSVは先頭200件です。
- 商品マスタの承認・正規化やERP連携を備えた本格PIMではありません。商品情報と掲載箇所・原稿・指示の関係を確かめる実証版です。

## 検証

`python -m unittest discover -s tests -v`

`node tests/browser-check.cjs` はPlaywright、提供ZIP、同梱Pythonを利用したブラウザー検証です。ポート8766と `.qa/` の独立データで実行し、テキスト保存・再読み込み、原稿入力、ページ追加、検索、改ページ、出力、公開、役割制限を確認します。

ブラウザー検証の準備は `npm install` と `npx playwright install chromium`。`CATALOG_PYTHON` にPython実行ファイル、`CATALOG_SAMPLE` に提供サンプルZIPのパスを環境変数で指定してください。この検証は提供サンプルの内容を前提にしています。通常のPythonテストは合成IDMLを生成し、実サンプルがない場合は実データの1件のみスキップします。
