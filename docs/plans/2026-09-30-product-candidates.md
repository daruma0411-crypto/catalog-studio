# 第2段階の最初の単位：商品候補と出典確認

承認済み要件のR02/R08/R21と商品DB生成の基礎を実装する。今回の完了範囲は単一カタログの候補抽出・同型番の掲載一覧・価格/画像/説明候補の人による確認。複数冊子横断、正規商品マスタ、旧新型番統合、AI自然文回答は未完了と明記する。

設計：IDML取り込み時に型番形式の候補と個々の出典を抽出。価格は円記号/円の明示がある数値のみ。型番候補数と掲載数を分ける。価格・画像・説明は同一枠/手動グループ/近接を根拠に候補提示するが自動確定しない。販促のみ対応確認・候補除外を保存でき、開発は閲覧のみ。社内閲覧者/APIの公開商品DBはまだ追加しない。

確認は出典ごとに保存。対象テキスト/候補資料/位置などのfingerprintと紐付け、変化すれば再確認として表示し確認履歴を保持。消失した候補の確認記録は削除せず件数を表示。版競合は既存の楽観ロックを利用。追加価格の創作・紙面の自動書き換えは行わない。既存IDMLは読み取り時にも生成できる。

リスク：強化。誤価格対応と確認済み誤表示を重点検証。元データを外部AIに送信せず、既存DBの追加JSON項目で扱う。

手順（writing-plans/executing-plansによるインライン実装）：
1. 抽出・複数掲載・単位/寸法の除外・誤対応保留・権限・元情報変更の再確認・CSV出典のテストを先に作る。
2. catalog_core/products.py とService/APIに自動抽出・読み取り・確認保存を接続。
3. static/products.jsを追加し「調査・データ活用」に商品候補一覧への入口、型番/価格/出典・確認画面・CSV出力を接続。
4. 実サンプルの候補件数と既知の重複型番を確認。Python/JSテストと専用DBの画面確認、最終レビュー後Railwayへ配置。
5. 要件案の最新進捗を非公開の別紙に追記し、未完了の範囲を区別する。
