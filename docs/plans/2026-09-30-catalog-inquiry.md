# 文章の依頼から商品・価格一覧を返す

ユーザーが承認した「型番と価格を一覧にしてと頼むと表で返す」設計を実装する。候補一覧への案内だけでは完了としない。

リスク：強化。質問の解釈違いと未確認価格の確定表示に注意。自由なAI接続はデータ送信先・契約が未確定のため追加せず、構造化データに対する読み取り限定の質問処理を採用。一般的な一覧依頼、特定型番の価格、型番の掲載数/場所を扱い、未対応の質問や条件は明示する。任意SQLや書込みは許可しない。

実装順序：
1. tests/test_inquiry.pyで自然文の価格一覧、型番抽出、掲載数、未対応、閲覧権限、確認済み限定をRED。
2. catalog_core/inquiry.pyで質問を型付き処理へ変換し、既存商品候補と確認記録/出典を表に整形。Service/HTTPにinquiryとCSVを追加。
3. static/inquiry.jsで回答表・価格の根拠と未確認表示・紙面遷移・CSVを表示。既存検索フォームを接続する。元の文字列検索APIは維持。
4. 単体/HTTP/ブラウザーでユーザーの実際の文を入力し、0件の文字検索ではなく表が返ることを確認。実データの誤確定なしと既存権限を確認。
5. 既存Railwayへ反映、読み取りで公開検証、GitHub同期、要件進捗と判断記録更新。

一覧は掲載ごとに保持。同じ枠の価格も複数型番が含まれ得るため未確認。確認済みの価格と別列にする。未知の質問を理解したふりで答えない。

## 検証
Python63件、Node6スイート成功。後続の条件ガード修正後、質問8件と関連UI2スイートを再確認。レビューで未対応の否定/除外/ページ/価格区分条件を黙って無視する問題を発見し、対応語彙以外が残ればunsupportedに修正。古い掲載場所結果も版一致時のみ表示。ローカルブラウザーでユーザーの実際の文章から価格表が返ることを確認。

任意の質問に答える生成AIではなく、対応している依頼を構造化データの読み取り処理へ変換する機能。価格条件/比較/期間/除外/ページ指定等は未対応を明示。未確認の近接候補を確定価格として返さない。
