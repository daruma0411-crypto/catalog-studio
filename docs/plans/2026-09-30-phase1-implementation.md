# 第1段階：原稿管理と再取り込み

承認済みの22項目要件のうち、原稿受け取り・質疑・合意・制作指示・紙面確認を実装する。今回は商品DB・AI校正・CG制作を実装済みと扱わない。

## 方針と影響
- SQLiteの既存JSON状態に追加フィールドを持たせる。既存レコードは省略値を許容し、破壊的なDB移行は行わない。
- 原稿の内容改訂番号と、合意・紙面確認した改訂番号を区別する。原稿本文・対象・資料の変更で再確認へ戻す。担当・期限だけの変更では合意を解除しない。
- Excel/CSV再取込は明示された取り込み元名＋安定した原稿IDを使用し、差分を事前表示する。ファイル名や行番号を同一性の根拠にしない。
- 競合はExcel採用・システム保持の選択を必要とする。欠損行は自動削除しない。取り込み失敗・切り捨ては0件成功にしない。
- 既存の紙面・素材・認証設定を維持してRailwayの同じサービスに配置する。

## タスク
1. `tests/test_workflow.py`：担当/期限保存、日付検証、内容変更で再確認、メタデータ変更で合意維持、原稿更新権限、質疑再開、編集履歴をテストしてから `catalog_core/submissions.py` を作る。`operations.py` と `service.py` に接続。
2. `tests/test_submission_import.py`：同一再取込、行順変更、同名別原稿、欠損/重複ID、競合、切り捨て、読取専用、競合版の拒否をテスト。`catalog_core/submission_import.py`、プレビューAPI、更新操作を作る。
3. `static/dashboard.js` と `static/submissions.js`：担当・期限・要対応の絞り込み、原稿詳細編集・履歴、取込元と列対応・差分プレビュー。`app.js` にイベントとAPI接続。既存の原稿カードと管理表を一緒に使えるようにする。
4. `catalog_core/exports.py`：日本語操作名と対象ページ、原稿の状態・改訂・担当・期限を出力。CSVは数式として解釈される文字を無害化する。
5. Python全テスト、JS構文/純粋関数テスト、専用データのブラウザー操作。レビュー・修正後にコードのみを配置し、実データは読取確認する。

## 重点検証
- 旧データに担当・改訂・期限フィールドがない場合も表示できる。
- 不正日付・空日付・当日期限・完了案件の期限切れ表示。
- 同一IDを複数行に含む取り込みは部分反映しない。
- ローカル編集と更新Excelの競合を検出し、保存直前の版変更も拒否する。
- 合意後に原稿本文/資料/質疑が変わった時、古い合意を最新と表示しない。

## 検証コマンド
`python -m unittest discover -s tests -p 'test_*.py'`

`node --check static/app.js` と変更したJSモジュールの構文確認。

ブラウザーは専用テストDBで新規→担当/期限→質問/回答→合意→紙面確認→本文改訂→再確認→Excel差分取り込みを実施。ライブデータを検証用に変更しない。

## 判断記録
既存のデモ用役割を維持し、担当者名は入力可能とする。本番個人アカウント・SSOは本番化の別要件。Excelの元様式が未提供のため、列を選ぶ取り込み画面を作り、独自の業務様式を強制しない。顧客固有の仕様書は公開リポジトリへ含めない。

## 実装・検証結果（2026-09-30）

第1段階を実装。Python42件、Nodeの期限/フィルターとプレビュー固定の2本が成功。専用テストDBで担当・期限、初回CSV取り込み、合意後の本文改訂、再取り込みの競合・選択漏れの通知・システム内容保持、紙面確認、担当者絞り込み、更新履歴をブラウザーで確認。コンソールエラーなし。

レビューで見つかった非同期プレビューと保存設定の不一致は、設定/カタログ/利用者/版番号の固定と処理中操作制限で修正。寸法メタデータのないXLSXの部分取り込みは実データの寸法再計算で防止し、境界テストを追加。再レビューに重要な残件なし。商品DB・AI質問・AI校正は本段階に含まない。
